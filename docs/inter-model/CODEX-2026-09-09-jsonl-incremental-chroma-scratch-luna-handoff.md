## What to build

Extend the merged one-adapter JSONL scratch prototype so its generation
projection uses the repository's existing real Chroma persistence and
writer/pruner operations under a fresh, tokenized temporary root. Preserve the
reviewed incremental state machine, replay behavior, stable identities, and
frontier counters. Produce bounded evidence and stop for independent review.

**Why this exists:** Kiro independently passed the original prototype but
identified one non-transferable seam: its generation store was an atomic JSON
stand-in, not the actual Chroma persistence/writer/pruner behavior. This pass
closes only that scratch evidence gap.

## Fixed execution boundary

Before importing Chroma, adapters, ingest, config, or provider code, each worker
must establish the existing `ScratchBoundary`, install socket denial, and run
from the allowlisted `sanitized_worker_env`. Every mutable path must resolve
under the fresh root and be validated before construction:

- source fixture and runtime snapshot;
- Chroma directory;
- config file and processed/checkpoint/export state;
- writer lock, attestation directory, census directory, and scratch PID lock.

Reject production paths, aliases, symlink components, inherited production
overrides, credentials, provider endpoints, and defaults that resolve outside
the scratch root. Use a new subprocess process group, closed file descriptors,
and descendant termination from the existing isolation harness.

## Integration points

- `scratch_jsonl_prototype/engine.py` — preserve source selection, continuity,
  checkpoint, generation, frontier, and fault-transition semantics.
- New scratch-only projection adapter, preferably
  `scratch_jsonl_prototype/chroma_projection.py` — map generation upsert/read/
  prune to the real `ChromaStore` methods without modifying `chroma_store.py`.
- `chroma_write_store.py` — reuse existing production writer-session behavior
  with a fully explicit scratch config plus scratch-local `lock_path`,
  `attest_dir`, and `census_dir`; do not edit this file unless a concrete
  contradiction is found and reported to Codex.
- `tests/scratch_jsonl_isolation_worker.py` and focused new tests — subprocess
  entrypoint and crash/replay evidence.

## Required behavior

1. Construct a complete scratch-only configuration. Do not load the user's
   default ConvMem config and do not inherit any production path.
2. Enter the existing real writer boundary/session against the scratch Chroma
   directory. If the production factory cannot safely accept a fully isolated
   config, stop and report the exact contradiction; do not weaken isolation.
3. Store deterministic scratch summaries/units using real
   `ChromaStore.add_summary` / `add_unit` or their exact current equivalents.
4. Prune obsolete generation rows using real source-scoped delete operations.
   Pruning must never select rows outside the scratch source identity.
5. Use deterministic local embeddings and documents of fixed dimensions.
   Summary, distillation, embedding, dedupe, reranking, and provider calls must
   remain fakes; no Ollama, DeepSeek, Hugging Face, HTTP, or socket access.
6. Reopen the same scratch Chroma directory after abrupt worker exit and replay.
   Compare authoritative Chroma rows and checkpoint authority with a clean full
   rebuild on identical frozen inputs, without normalization.
7. Preserve the original frontier claims: unchanged replay makes zero
   transforms; one-record append transforms only the dependency frontier; old
   rows are reused.
8. Discover and inventory every new durable authority transition introduced by
   the Chroma seam. Add before/after subprocess crash cases and a coverage
   assertion that fails if either side of a transition is missing.

## Required matrix

- Original isolation gate, including production-path/symlink/provider/network
  rejection and crash-descendant containment.
- Append, exact boundary, partial record, and partial-record completion.
- Prefix mutation, truncation, replacement/rotation, and transform-fingerprint
  fallback.
- Crashes before/after each upsert, publication/authority selection, prune,
  checkpoint prepare/publish, fallback marker/cleanup, lock transitions, and
  every Chroma-specific durable transition discovered during implementation.
- Stale-lock recovery.
- Incremental-versus-clean full-rebuild equivalence for Chroma ids, documents,
  embeddings, metadata, generation authority, and checkpoint fields.
- Frontier-bounded transform counters, including unchanged replay = 0.
- Negative controls proving attempted production configuration, real provider,
  localhost provider, and outbound network access fail before resource use.

Luna may implement the scratch adapter, worker modes, focused tests, crash
matrix, static cleanup, and evidence updates. Stop and return to Codex if any
of these occur:

- satisfying the test requires modifying production code;
- the real writer factory loads or reaches a production path despite explicit
  scratch configuration;

- network/provider access cannot be denied before imports;

- a new durable authority transition lacks a deterministic replay rule.

Do not polish or redesign the frozen prototype in the absence of one of these
concrete contradictions.
